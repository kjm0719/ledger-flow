# Ledger Flow
가상 포인트 송금과 거래 원장 정합성을 검증하는 로컬 백엔드 포트폴리오 프로젝트.

## 바로 실행
Node.js 24 이상 필요. 외부 npm 패키지는 없습니다.
```powershell
npm start
```
브라우저에서 http://127.0.0.1:3000 접속. Windows에서는 start.cmd를 실행해도 됩니다.
포트폴리오 설명: http://127.0.0.1:3000/portfolio
종료: 터미널에서 Ctrl+C. 데이터는 data/ledger.sqlite에 유지됩니다.
포트 3000 사용 중이면 PowerShell에서 `$env:PORT=3100; npm start`로 변경합니다.
DB_PATH 환경 변수로 별도 SQLite 파일 경로를 지정할 수 있습니다.

## 검증
```powershell
npm test
npm run check
```
테스트는 임시 DB를 사용하며 데모 데이터를 수정하지 않습니다.
검증 대상: 정상 송금, 재전송, 요청 키 충돌, 잔액 부족, 입력 검증, 저장 중 실패 롤백,
재시작 후 지속성, 원장 변경 방지/잔액 변조 감지, 조회/페이지네이션,
동일 키 HTTP 동시 요청, 초과 인출 HTTP 동시 요청, HTTP 계약.

## 2분 데모
1. 총 175,000 P와 세 지갑의 잔액을 확인합니다.
2. 앨리스 → 밥으로 1,000 P를 송금합니다. 앨리스 99,000 P, 밥 51,000 P.
3. '마지막 요청 그대로 재전송'을 누릅니다. 200/replayed=true를 반환하며 거래 수와 잔액은 그대로입니다.
4. 앨리스 → 밥으로 100,000 P를 요청합니다. 잔액 부족(409)이며 원장이 추가되지 않습니다.
5. 원장 검증 상태와 API 응답을 확인합니다. 새로고침 후에도 기록이 유지됩니다.
새 DB 기준 예시입니다. 기존 거래가 있으면 잔액은 달라집니다.

## 핵심 설계
- BEGIN IMMEDIATE부터 COMMIT까지 키 확인, 조건부 차감, 입금, 거래, 원장 두 항목을 하나의 트랜잭션으로 처리합니다.
- Idempotency-Key UNIQUE로 성공 요청을 식별합니다. 같은 키와 같은 내용은 기존 결과를 반환하고 다른 내용은 409입니다.
- 금액은 1~1,000,000 정수 포인트만 허용합니다. 부동소수점 금액을 받지 않습니다.
- 잔액은 balance >= amount 조건을 만족할 때만 차감합니다. DB CHECK로 음수 잔액도 방지합니다.
- entries는 음수 출금과 양수 입금 한 쌍입니다. 송금마다 합계 0을 검증합니다.
- 원장과 거래의 UPDATE/DELETE는 트리거로 차단합니다. DB 관리자까지 막는 위변조 방지 기술은 아닙니다.
- 현재 잔액과 초기 잔액+원장 합계를 교차 검증하며 총 발급량 보존을 확인합니다.
- 실패 요청의 키는 저장하지 않습니다. 실패 후 동일 키 재시도는 그 시점의 잔액으로 다시 평가됩니다.
- 외부 의존성과 설정 시간을 줄이기 위해 Node.js 내장 HTTP/SQLite와 순수 JavaScript를 사용했습니다.
- SQLite 동기식 실행은 요청을 직렬 처리합니다. 동시 HTTP 테스트는 이 단일 프로세스 환경에서의 결과이며 분산 환경 성능을 의미하지 않습니다.

## API
| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /api/health | 로컬 서비스 상태 |
| GET | /api/wallets | 지갑과 현재 잔액 |
| POST | /api/transfers | 송금. Idempotency-Key 헤더 필수 |
| GET | /api/transfers?walletId=alice&limit=5&offset=0 | 지갑 필터/페이지네이션 |
| GET | /api/audit | 잔액·원장·총량 교차 검증 |

송금 요청 예시:
```json
{"senderId":"alice","recipientId":"bob","amount":1000,"memo":"작품 구매"}
```
헤더: Content-Type: application/json, Idempotency-Key: demo-request-001
결과: 신규 성공 201, 동일 요청 재전송 200, 잔액 부족/키 충돌 409,
잘못된 입력 400, 지갑 없음 404, 다른 출처 403, JSON 아님 415, 요청 8KB 초과 413.

## 범위와 한계
실제 돈, 토큰 또는 블록체인을 다루지 않는 가상 포인트 데모입니다.
사용자 인증/인가, 실제 결제, 외부 블록체인 연결, 배포, 분산 시스템, 환불, 운영용 감사 로그는 구현하지 않았습니다.
127.0.0.1에만 바인딩하고 로컬 Host/Origin을 검사합니다. 데모 지갑은 모두 조작할 수 있으므로 인증을 추가하기 전에는 공개 서버로 운영하면 안 됩니다.
GET 지갑 목록과 별도 audit 요청은 화면 전체에 대한 단일 스냅샷이 아닙니다. 감사 API 내부는 읽기 트랜잭션으로 일관된 값을 읽습니다.
초기 잔액은 데모 발급값으로 따로 저장됩니다. 송금 원장만 출금/입금 쌍을 기록하며 회계 시스템 전체를 구현한 것은 아닙니다.
실서비스 확장 시 PostgreSQL과 행 잠금, 인증/권한, 관측/알림, 백업/복구, 정정 거래 모델을 검토해야 합니다.
