# 제출 전 20분 확인
이 문서는 암기용 모범 답안이 아니라 실제 코드를 따라가는 안내입니다.

## 0~5분: 화면 실행
npm start로 실행하고 1,000 P 송금, 같은 요청 재전송, 잔액 부족을 직접 확인하세요.
재전송 버튼은 저장한 동일 body와 동일 key를 사용합니다.
송금 실행 버튼을 다시 누르면 새 key를 생성하므로 별도 거래입니다.

## 5~10분: src/ledger.js 읽기
transfer 함수에서 BEGIN IMMEDIATE, previous 조회, UPDATE wallets, INSERT transfers,
두 번의 INSERT entries, COMMIT, ROLLBACK을 순서대로 찾아보세요.
'원장 저장 중 실패하면 잔액은 어떻게 되나?'에 답하고 롤백 테스트를 확인하세요.

## 10~15분: 테스트 재현
npm test를 실행하세요. 저장 실패 테스트는 두 번째 원장 INSERT에 오류를 강제로 발생시킵니다.
동일 키 요청 20개 중 1개만 신규 성공이어야 합니다.
10,000 P 요청 20개 중 초기 100,000 P에서 10개만 성공해야 합니다.

## 15~20분: 본인의 변경
예를 들어 메모 최대 길이를 바꾸고 입력 검증과 화면 제한을 같이 수정해 보세요.
변경 이유와 영향, 확인 결과를 직접 적으세요. 실제로 한 작업만 기여로 설명하세요.

## 자주 나올 질문
- 멱등성이란? 같은 작업 식별자로 재시도해도 성공한 송금 효과는 한 번만 발생하는 것.
- DB 트랜잭션은 왜? 잔액만 변하고 원장이 없거나 수취인에게 입금되지 않는 부분 성공을 막기 위해.
- 같은 키에 다른 금액이 오면? 기존 요청과 다르므로 409를 반환한다.
- 실패한 키는? 저장하지 않는다. 재시도 때 현재 상태를 기준으로 다시 평가한다.
- 원장 불변성이 완전한가? 아니다. SQL 트리거는 정상 경로의 변경을 제한한다. DB 관리자는 우회할 수 있다.
- 동시성을 어떻게 처리하나? 현재 Node 프로세스의 동기식 SQLite 호출은 직렬 실행된다.
  BEGIN IMMEDIATE로 쓰기 예약을 잡고 조건부 UPDATE를 수행한다. 다중 서버 검증은 별도 과제다.
- 블록체인인가? 아니다. 블록체인/금융 백엔드와 연결되는 정합성 주제를 다룬 로컬 포인트 서비스다.
- AI는 어디에 사용했나? 초기 코드, 테스트, 문서 생성에 사용했다. 직접 검토·수정·재현한 부분만 추가로 설명한다.
